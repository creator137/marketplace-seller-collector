Как это работает

Кратко о сборе, сессиях, справочниках и обогащении данных.

Сбор продавцов

  1. Поиск. Адаптер находит продавцов в выбранных категориях (и городах — для Wildberries).
  2. Детали. По найденным id подтягиваются название, рейтинг, ИНН, адрес и другие доступные поля с маркетплейса.
  3. Обогащение. Если есть ИНН — контакты и реквизиты дополняются через DaData (без затирания данных маркетплейса).
  4. Лимит по городу. В форме «Сколько собрать» — сколько продавцов из выбранных городов нужно набрать. Сбор продолжается, пока цель не достигнута (город определяется по юр. адресу).
  5. Результаты. Прогресс — в истории запусков; таблица и экспорт XLSX — в разделе «Продавцы» или на странице задачи.

Зачем нужна сессия маркетплейса

Ozon, Wildberries и иногда Яндекс.Маркет блокируют запросы без «живой» пользовательской сессии (cookies после прохождения проверки в браузере). Без сессии задача уходит в статус Приостановлен — это не пустой успешный результат.

Как сохранить сессию

  1. На своём компьютере выполните команду bootstrap для нужного маркетплейса:
python manage.py bootstrap_sessions --marketplace ozon
python manage.py bootstrap_sessions --marketplace wildberries
python manage.py bootstrap_sessions --marketplace yandex_market
  1. В открывшемся окне браузера пройдите captcha/проверку вручную и нажмите Enter в терминале.
  2. Cookies сохранятся в runtime/sessions/ и автоматически подхватятся при следующем сборе.
  3. Либо вставьте cookies вручную в справочнике Сессии маркетплейсов (раздел «Справочники») или в .env (OZON_COOKIES, WB_COOKIES, YANDEX_MARKET_COOKIES).

Сессии со временем истекают. Если сбор снова остановился с блокировкой — обновите сессию и нажмите Продолжить сбор на странице задачи (прогресс не теряется).

Для чего нужны справочники

Раздел Справочники (Django Admin) — это настройка системы без правки кода.

Города
Список городов в форме сбора и для определения города продавца по юр. адресу. Для Wildberries можно указать dest-код доставки. Начальные: Уфа, Челябинск, Екатеринбург.
Категории
Привязаны к маркетплейсу. В форме показываются только категории выбранной площадки. external_id — поисковый запрос или путь категории на сайте. Без активных категорий сбор не запустить.
Сессии маркетплейсов
Хранение и обновление cookies. После сохранения файл сессии сразу читают worker и адаптеры — перезапуск не нужен.
Продавцы и задачи
Просмотр и поиск уже собранных записей, контактов и истории запусков (дублирует UI, удобно для правок).

DaData

Единственный внешний источник обогащения. Нужен токен DADATA_TOKEN в .env. По ИНН дополняются название, юр. адрес, телефоны, email, сайт — если маркетплейс их не отдал.

Если DaData ничего не нашла — это нормально, задача не падает. Повторный запрос по тому же продавцу обычно пропускается несколько недель (DADATA_TTL_DAYS).

Важно знать

  • Повторный запуск не создаёт дублей: продавец уникален по маркетплейсу + внешнему id.
  • Телефоны и email чаще приходят из DaData, а не с витрины маркетплейса.
  • Ссылка Telegram строится из мобильного номера технически — это не проверка аккаунта.
  • Яндекс.Маркет: список продавцов из поиска обычно доступен; страница продавца часто требует cookies.
  • Ozon/WB без актуальной сессии часто отдают 403 — обновите cookies и продолжите задачу.
